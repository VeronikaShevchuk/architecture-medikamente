# Механизм тегирования конфиденциальных данных — МЕДИКАМЕНТЕ TO-BE

## Цели тегирования
1. Автоматически идентифицировать чувствительные данные
2. Контролировать доступ на основе тегов
3. Запрещать выгрузку/передачу запрещённых категорий
4. Обеспечить аудит по тегам

## Схема тегов

| Тег | Значение | Пример данных | Действие по умолчанию |
|-----|----------|---------------|----------------------|
| `pii` | Персональные данные | ФИО, телефон, email | Шифрование + аудит доступа |
| `special_pii` | Специальные категории | Диагнозы, генетика | Шифрование + отдельное согласие |
| `biometric` | Биометрия | Фото, отпечатки | Шифрование + ограниченный доступ |
| `financial` | Платёжные данные | Номер карты (токен) | Токенизация, не хранить CVV |
| `restricted` | Ограниченный доступ | Данные о детях, ВИЧ | Доступ только по запросу |
| `anonymized` | Обезличенные | Агрегаты для BI/ML | Свободное использование |
| `medical` | Медицинские (не special) | Рост, вес, давление | Доступ врача и пациента |
| `contract` | Договорные документы | Сканы договоров | Шифрование + срок хранения |
| `audit_only` | Только для аудита | Логи доступа | Неизменяемость |
| `to_delete` | Подлежит удалению | Данные по запросу клиента | Автоматическое удаление через N дней |
